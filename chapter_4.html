第四章 R/C延时计算

4.1 程序主体

程序脚本文件名称：iccad_ladder.py

程序说明：R/C梯形网络是互连线延时分析中最简单的集总模型。把一条长连线切成N段，每一段用一个串联电阻和一个接地电容来代表，就得到本章的N级R/C梯形。阶数N越大，梯形越接近分布参数的RC传输线；在集成电路互连、时钟树和长信号线的延时估算中，这种模型是理解Elmore延时和SPICE瞬态仿真的起点。
本程序用后向欧拉法(Backward Euler)求解1V阶跃输入下梯形末端节点的电压波形，用Elmore公式估算延时，并用Matplotlib把N=5、10、20、50四种阶数的波形画在同一张图上；程序不依赖外部网表，也不含图形用户界面，适合观察参数变化对波形和延时的影响。

4.2 问题需求和算法背景

经过程序运行并观察输出波形，可以对程序要解决的问题做一归纳：
已知一个N级均匀R/C梯形网络，每一级由一个串联电阻R和一个接地电容C构成，输入端为1V阶跃电压源（含1Ω源内阻），需要：

  1. 计算末端节点电压随时间的波形，并绘制不同阶数N的曲线；
  2. 计算该梯形的Elmore延时，并与仿真得到的50%延时比较；
  3. 通过改变N、时间步长Δt等参数，观察数值方法的稳定性与精度。

4.2.1 从互连线到R/C梯形

在集成电路中，长互连线的电阻和电容不能再忽略。把一条线均匀分成N段，每一段用串联电阻R表示，每个节点用接地电容C表示，就得到图4-2所示的N级R/C梯形。这里的N是节点数，也是电容个数；节点0到节点N-1之间有N-1个串联电阻，节点0还通过一个1Ω的源内阻R_s接到1V理想电压源V_s。因此整个网络中共有N个电阻（N-1个串联电阻加1个源内阻）和N个电容。

图4-2 N级R/C梯形网络与1V阶跃源

对节点0、内部节点i和末端节点N-1分别列KCL。取电容电流从节点流向地、电阻电流从该节点流向相邻节点的方向为正，可得：

Cdtdv0​​Cdtdvi​​CdtdvN−1​​​=−Rv0​−v1​​−Rs​v0​−Vs​​=Rvi−1​−2vi​+vi+1​​,i=1,2,…,N−2=RvN−2​−vN−1​​​(Equ. 4-1)

当N=1时，节点0同时是末端节点，网络中只有源内阻和电容，方程退化为C dv_0/dt = -(v_0-V_s)/R_s，代码中的G也只有一项-1。这一点在阅读ladderWave( )时容易忽略，先在这里说明。

把N个节点的电压排成列向量v，把电容排成对角矩阵C，把电阻关系排成矩阵G，再令i_s为注入各节点的电流向量，则方程(4-1)可以统一写成：

Cdtdv​=Gv+is​(Equ. 4-2)

对于本章的单位梯形，C是N×N的单位矩阵；G是三对角矩阵，主对角线在节点0和内部节点处为-2，在末端节点处为-1，相邻对角线为+1；i_s只有第一个元素为1，其余为0。需要特别说明，代码中的G并不是通常意义下的节点电导矩阵，而是它的相反数。若把通常的节点电导矩阵记为L（对角为+2、末端为+1、相邻为-1），则节点方程本应写成L v + C dv/dt = i_s；代码把L取负号记作G，于是写成C dv/dt = G v + i_s。这样写只是符号约定，不影响结果，但读者若把G当成正的电导矩阵，就会对-2和-1感到困惑。

为什么节点0的对角是-2？因为当N>1时，节点0连接两条电阻支路：一条是到节点1的串联电阻R，另一条经源内阻R_s到理想电压源；固定电压源在瞬态分析中可视为交流地。在本程序中R=R_s=1，这两条支路对节点0的电导各为1，所以对角为-2。当N>1时，末端节点只连一个到节点N-2的串联电阻，所以对角从-2调整为-1。源内阻的处理也可以用诺顿定理理解：1V理想电压源与1Ω内阻串联，等效为1A电流源与1Ω电阻并联；i_source[0]=1就是这1A电流源，而节点0对地的1Ω电阻则体现在G[0][0]的第二个-1中。

4.2.2 Elmore延时

Elmore延时是互连线延时分析中最常用的一阶估算量。它定义为冲激响应的一阶矩，也可以理解为“每个电容的电容值乘以从输入到该电容的路径电阻”之和。对树状RC网络，这个求和有明确的公式，因此不需要先做瞬态仿真就能快速估算延时。

对本章的均匀梯形，源内阻R_s在输入端，它看到下游全部N个电容，贡献为R_s·C·N；节点i-1与节点i之间的串联电阻（i=1,…,N-1）看到下游N-i个电容，贡献求和后为R·C·(N-1)+R·C·(N-2)+…+R·C，即R·C·N(N-1)/2。因此总Elmore延时为：

τN​=Rs​CN+RC2N(N−1)​(Equ. 4-3)

当R_s=R时，上式化为τ_N = RC·N(N+1)/2；本章取R=C=1，于是τ_N = N(N+1)/2。这就是elmoreDelay( )中n*(n+1)/2的来历。N=1时τ=1，N=2时τ=3，N=10时τ=55，N=50时τ=1275。

实际观察50%延时的时候，通常用一阶RC的公式来近似。对一阶RC电路，阶跃响应为1-exp(-t/RC)，令其等于0.5，得到t=RC·ln2≈0.69RC。因此程序中用

t50​≈0.69τN​(Equ. 4-4)

作为50%延时的估算。0.69是ln2≈0.693的常用近似，对一阶RC基本准确；但对N级梯形，网络有多个极点，50%延时并不严格等于0.69τ_N。N越大，0.69τ_N与真实50%延时的相对偏差越明显；4.4节会用仿真数据说明这一点。

还需要强调，Elmore延时本身只是一个一阶矩，它不能完整描述波形的上升时间、过冲和振荡；它给出的是延时的一个保守估计，而不是精确的50%时刻。在高阶互连、电感效应明显或传输线效应不可忽略时，需要更精确的模型或SPICE瞬态仿真。

4.2.3 后向欧拉法

方程(4-2)是N个一阶常微分方程组成的方程组，除N=1等极简单的情形外，一般没有便于手算的解析解；程序中用后向欧拉法(Backward Euler)把它离散成线性递推式。设时间步长为Δt，第k步的节点电压向量为v^k，把方程(4-2)中的导数用后向差分近似，并在右端取第k+1步的电压：

CΔtvk+1−vk​=Gvk+1+is​(Equ. 4-5)

把含v^{k+1}的项移到左边，两边左乘C^{-1}，得到：

(I−ΔtC−1G)vk+1=vk+ΔtC−1is​(Equ. 4-6)

记

A=I−ΔtC−1G,B=ΔtC−1is​(Equ. 4-7)

则每一步只需求解A v^{k+1}=v^k+B，即

vk+1=A−1(vk+B)(Equ. 4-8)

因为A只依赖C、G和Δt，不随时间变化，程序在进入时间循环之前就算好Ainv；B在阶跃输入下也是常量，所以循环内只需要做一次矩阵-向量乘法和一次向量加法。若输入电流源随时间变化，B就要在每一步重新计算；若电容值随时间变化，C和A也要更新。

后向欧拉法是A-稳定方法，对本章这样的刚性RC网络，即使Δt取得较大也不容易发散；但“稳定”不等于“准确”，Δt过大时波形的时间分辨率会变差，早期细节会被抹平。前向欧拉法(Forward Euler)的稳定性条件要苛刻得多，Δt稍大就可能振荡发散；这一点留作练习。

代码中还有一个时间索引的细节需要说明。time列表从0开始，但循环内先执行v_nodes = Ainv·(v_nodes+B)，再把结果追加到vout；因此第一个记录点虽然标成t=0，实际对应的是t=Δt的电压。tpdMode在判断v_nodes[N-1]>0.5时使用的tt是更新前的时间，所以它打印的50%时刻比真实50%穿越点小一个Δt。这个偏移不影响定性结论，但读数值时应留意；修正方法留作练习。

从物理上还可以做两个检查：初始时刻所有电容电压为0，所以v_nodes从零向量开始；当t趋于无穷大时，电容相当于开路，梯形中的串联电阻没有电流，所有节点电压都等于电源电压1V；源内阻上仍有1A的直流电流（诺顿电流源的电流全部流过它）。程序运行足够长时间后，末端电压应趋近1V；若结果偏离这个值，就说明矩阵组装或时间推进有误。这两个检查也是调试类似瞬态程序时最常用的手段。

4.3.2 elmoreDelay( )

{{#include ./resources/chpt4/iccad_ladder.py.nl:9:16}}
代码4-4

elmoreDelay( )只有两行有效代码：先算d = n*(n+1)/2，再返回d*0.69。其中n是梯形节点数，公式来自4.2.2节的τ_N=N(N+1)/2；0.69是ln2的近似，用来把Elmore延时换算成50%延时的估算值。函数的文档字符串说明它是“单位R/C梯形的Elmore延时计算器”，并提醒0.69这个常数在讲义中会特别强调。

这个函数的单位是隐含的：代码把R、C都取为1，所以d的数值单位是Ω·F，即秒。N=1时d=1，返回0.69s；N=2时d=3，返回2.07s；N=10时d=55，返回37.95s。与4.4节的仿真值对照可以看到，N=1时0.69τ与仿真50%延时几乎相等，N≥2时0.69τ偏小，说明0.69这个一阶RC系数不能无条件套用到多阶梯形上。

这个函数目前没有R、C参数，只适用于单位梯形；如果要把R、C改成任意值，需要把公式改成R_s·C·N+R·C·N(N-1)/2，再乘0.69。这个推广留作编程练习题4.1。

4.3.3.1 矩阵组装

{{#include ./resources/chpt4/iccad_ladder.py.nl:33:52}}
代码4-5

代码4-5首先把单位电容和单位电导分别赋给c_val和g_val，然后用三个列表描述矩阵的非零元素：diagC是C的主对角，diagG是G的主对角，sub_diagG是G的次对角。因为本章取R=C=1，diagC全是1，diagG全是-2，sub_diagG全是1；如果以后要支持不同的R、C，只需要改这三个列表的生成方式。

NumPy的np.diag( )有三种常见用法：np.diag(v)把一维数组v放在主对角上生成对角阵；np.diag(v,-1)把v放在主对角下方一条对角线上；np.diag(v,1)把v放在主对角上方一条对角线上。代码先用np.diag(diagC)生成电容矩阵C，再用np.diag(diagG)加上下、上两条次对角，得到三对角矩阵G。

G[N-1][N-1] += g_val这一行是边界修正。当N>1时，末端节点只连一个到节点N-2的电阻，没有右边的相邻节点，所以主对角应从-2改成-1。节点0的情况则不同：当N>1时，它左边没有串联电阻，但有一个到理想电压源的源内阻，因此主对角保持-2；当N=1时，节点0同时是末端节点，只剩源内阻，主对角也被修正为-1。这个细节与4.2.1节的KCL方程完全对应。

代码中的print(C)和print(G)把两个矩阵打印出来，方便观察三对角结构；因为ladderWave( )被调用四次，输出会有四组矩阵，篇幅较长。若只想看波形，可以暂时把这两行注释掉；这不会影响计算。

代码4-6首先建立电流源向量i_source，并把第一个元素设为1。这就是4.2.1节所说的诺顿等效：1V理想电压源与1Ω内阻串联，等效为1A电流源与1Ω电阻并联；电流源注入节点0，节点0对地的1Ω电阻已经包含在G矩阵中，所以这里只需要一个1A的电流源。

接下来生成时间网格：

time = [x * deltaTime for x in range(start, int(endTime / deltaTime))]

当start=0、deltaTime=0.01、endTime=1000时，time为0、0.01、0.02、…、999.99，共100000个时间点。int( )把endTime/deltaTime截断为整数，避免浮点误差导致多出一个点；如果endTime不是deltaTime的整数倍，最后一个时间点会略早于endTime。

v_nodes是当前时刻所有节点的电压，形状为N×1；vout只保存末端节点的电压，形状为长度随迭代增加的一维列表；index记录已经推进的步数，最后用来截取time[0:index]，使返回的时间和波形等长。

代码中的注释给出了Forward Euler和Backward Euler的推导。Forward Euler用第k步的电压计算右端，Backward Euler用第k+1步的电压；本章采用后者，所以注释中最终写的是

(I - deltaT * C-1 * G) * vt1 = vt0 + deltaT * C-1 * i_source

其中C-1是inv(C)的简写。代码把左边的矩阵求逆预先算好：

Ainv = np.linalg.inv(np.eye(N) - deltaTime * np.dot(np.linalg.inv(C), G))
B = deltaTime * np.dot(np.linalg.inv(C), i_source)

np.eye(N)生成N×N单位阵；np.linalg.inv(C)求C的逆；np.dot做矩阵乘法。因为本章的C是单位阵，inv(C)其实也是单位阵，但代码仍然保留这个写法，以便将来支持非单位电容。Ainv只依赖C、G和Δt，在时间循环外算一次即可；B在阶跃输入下也是常量，所以循环内只需要重复做矩阵-向量乘法。若i_source随时间变化，B要在循环内重新计算。

4.3.3.3 时间循环、tpdMode与返回

{{#include ./resources/chpt4/iccad_ladder.py.nl:88:103}}
代码4-7

代码4-7是时间推进的主体。for tt in time:逐个取时间点，index += 1计数；v_nodes = np.dot(Ainv, v_nodes + B)完成一次后向欧拉更新，其中v_nodes + B是列向量相加，np.dot是矩阵-向量乘法。更新后的v_nodes再取出末端节点v_nodes[N-1][0]，追加到vout。

如果tpdMode为真，程序检查末端电压是否超过0.5V；一旦超过，就打印当前时间、节点号、电压值和Elmore延时，然后break退出循环。需要注意，if v_nodes[N-1] > 0.5:左边的v_nodes[N-1]是形状为(1,)的数组，NumPy对单元素数组允许布尔转换，所以这个写法能工作；更严谨的写法是v_nodes[N-1, 0] > 0.5，这样比较的是标量，打印时也不会出现数组格式。在较新的NumPy版本中，直接把单元素数组交给%f格式化还会产生DeprecationWarning；改成标量后可以同时避免这个警告。

前面已经提到时间索引的细节：tt是更新前的时间，v_nodes是更新后的电压，所以tpdMode打印的时刻比真实50%穿越点早一个Δt。若需要精确的50%时刻，可以在更新后用tt+deltaTime打印，或者在相邻两步之间做线性插值；这些修正留作练习。

函数最后返回vout, time[0:index]。正常跑完所有时间点时，index等于len(time)，返回全部点；tpdMode提前退出时，index正好等于已记录的步数，vout和time[0:index]长度一致，主程序可以直接把它们传给plot_wave( )。

实例二：时间步长的影响
